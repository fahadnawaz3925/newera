## 🐛 Bugs Discovered

1. **Invalid Gemini Model Fallback (`standalone-worker.js`)**
   - **Issue:** In the visual caption generation logic, the script attempts to use `gemini-3.5-flash` and then falls back to `gemini-3.6-flash`.
   - **Impact:** Google does not currently have a `gemini-3.6-flash` model. When the rate limit is hit on the first model, the fallback fails immediately with an invalid model or 429 error, preventing the AI caption from generating.
   - **Fix:** Update the fallback array to use actual existing models, such as `['gemini-1.5-flash', 'gemini-1.5-pro']`.

2. **Race Condition in Queue Grabbing (`standalone-worker.js`)**
   - **Issue:** Even with the recent updates to add `.eq('status', 'PENDING')`, fetching an item and then immediately updating it is technically not atomic in standard Supabase REST API calls. 
   - **Impact:** If two PM2 workers run at the exact same millisecond, they could theoretically pull the exact same queue item and process it twice.
   - **Fix:** Move the "claim queue item" logic into a PostgreSQL Stored Procedure (RPC) on Supabase that handles the atomic `SELECT ... FOR UPDATE` and `UPDATE` in a single transaction.

3. **Inconsistent Environment Variable Naming**
   - **Issue:** Scripts like `test_account1_api.js` tried to use `process.env.IG_ACCOUNT_ID_1`, but the actual variable in the `.env` file is `IG_BUSINESS_ACCOUNT_ID_1`.
   - **Impact:** Test scripts and local debuggers will fail with `undefined` properties.
   - **Fix:** Standardize the `.env` names across all one-off `test_*.js` scripts to match the main environment configuration.

## 🚀 Architectural Suggestions

1. **Decouple Video Download from Processing**
   - **Current:** The worker blocks and waits for `yt-dlp` to download the video. If the network is slow or the Oracle server connection drops, the worker hangs.
   - **Improvement:** Have a separate lightweight downloader agent that saves videos to a local `/tmp/` cache. The main `reels-worker` can then instantly pick up locally cached videos, applying ffmpeg filters much faster.

2. **Dynamic Account Configurations**
   - **Current:** The watermark texts (like `@thehouseofcobblers` and `@buffedboujee`) and accent colors are hardcoded inside `standalone-worker.js`.
   - **Improvement:** Move these configurations into the `reels_accounts` table in Supabase. The worker can fetch the watermark text, color, and intro/outro texts dynamically. This means you can add Account 4 without needing to redeploy or edit the code.

3. **Improve Error Logging**
   - **Current:** Errors caught during `processSingleItem` are stringified and pushed to the `error_log` column, but they are often truncated or missing stack traces.
   - **Improvement:** Implement a structured JSON logging system (e.g., using `winston` or `pino`) and store structured error details in Supabase, making debugging much easier from the dashboard.
